# 地籍共作平台

讓測量員外業回來，把**重測系統的資料夾**丟上來，大家就能在同一張地圖上看到彼此的**補點、參考點**，並對照**數值地籍圖**與整理過的**圖根點**。坐標一律換成 **TWD97**。

**不用伺服器、不用安裝、不用付費**：平台只是一個網頁檔，資料就放在所裡的共用資料夾（`\\Kcland-nas\kc外網共用\二課`），
資料只在機關網路裡流動，不會開任何連接埠，也不會傳到外面（只有底圖圖磚向國土測繪中心要）。

## 一、架設（管理者做一次就好）

1. 下載 **`dist/地籍共作平台.html`**（就這一個檔），放到 `\\Kcland-nas\kc外網共用\二課`。
2. 用 **Edge**（或 Chrome）打開它 → 按「📂 選共用資料夾」→ 選 `二課` → 瀏覽器問「允許編輯」按**允許**。
   - 平台會在裡面建一個 **`地籍共作平台資料`** 資料夾，所有資料都放這裡。
3. 第一次會跳到 **⚙ 管理**：按 **更新數值地籍圖 → 選 zip**（或選資料夾），選 `115-11-01數值.zip`。
   - 大約 10 秒～1 分鐘（看 NAS 速度）：判斷 67/97、換成 97、整理圖根點，存進共用資料夾。
4. 完成！叫大家打開同一個 HTML 檔、選同一個 `二課` 資料夾就好（可以在桌面做捷徑）。

> 之後每次打開，瀏覽器可能會再問一次能不能用這個資料夾，按「連接共用資料夾」→「允許」就好（Edge 有時會提供「每次造訪都允許」）。
>
> 數值地籍圖有新版時，管理者再做一次第 3 步。舊版底圖會留一份備份。

### 共用資料夾裡的東西

```
二課\
  地籍共作平台.html               ← 大家打開這個
  地籍共作平台資料\
    設定.json                     67 段清單、廢段、容許差、自訂段名
    底圖\目前.json                 現在用哪一版底圖
    底圖\v1793…\                  整理好的底圖（每段一個 JSON、圖根點、地號索引）
    底圖\數值原始檔\               上傳的數值 zip（改 67 清單、廢段時直接重算）
    上傳\20261105-091500_王小明\    每次上傳一個資料夾：結果.json + 原始檔\
```

- 每次上傳都是**獨立的資料夾**，好幾個人同時上傳也不會互相蓋掉。
- 「刪除」只是在那個資料夾放一個 `已刪除.json` 記號，檔案都還在；要救回來，把 `已刪除.json` 刪掉就好。
- **備份只要複製整個 `地籍共作平台資料` 資料夾。**

## 二、測量員與補點清冊（管理者先設定）

**⚙ 管理 → 測量員**：新增每位測量員的「名字＋補點代碼」，例如 林威帆／W。這位測量員的補點一律編成 **Q＋代碼＋流水號**（QW1、QW2…）。

- 代碼不能重複；移除測量員不會刪掉他上傳過的資料。
- **📒 補點清冊**：列出這位測量員所有的補點（點名、坐標、第一次登錄的日期、案件種類、地號），可以下載 CSV。
- **⬆ 匯入既有清冊**：平台啟用前已經有的補點，用 CSV（`點名,Y,X,段`，TWD97）匯入一次，之後的編號會從最大號接下去。

**⚙ 管理 → 設定**：案件種類（預設 保存登記、鑑界、分割，可以自己加）、補點「同一點」的距離（預設 2 公分）、參考點範圍（預設宗地界址點 50 公尺內）。

## 三、測量員：上傳外業資料（4 步）

1. 按綠色 **📤 上傳外業資料**，**選自己的名字**（第一次選就會記住）。
2. 選**案件種類**，填**這次測量的地號**（必填，例如 `123、124-1`；不同段寫 `1114 123、1113 45`），收件號可以不填。
3. 把重測系統的**整個資料夾**（例如 `KC1114`）拖進框框，或按「選資料夾」／「選檔案 / zip」。
4. 看系統讀到的內容，沒有紅色的問題就按 **✅ 上傳**（有紅色問題，例如地號在 D13 找不到，按鈕會鎖住）。

系統讀什麼：

| 檔案 | 讀出什麼 |
|---|---|
| `KCxxxx.D13` + `D14` | **只讀你填的那幾筆土地**：D13 找出這幾筆的界址點號，D14 取坐標，畫出這次的宗地範圍 |
| `KCxxxx.D14` | **參考點**（編碼不是 00 的點，例如 `5.30`）：只取這幾筆土地界址點附近（50 公尺內，或點號跟界址點一樣）的 |
| `KCxxxx.D20` | **全部補點**：跟這位測量員的**補點清冊**比坐標（2 公分內算同一點）→ 已經有的用原本的名字、不重複加；新的編成 Q＋代碼＋下一號 |
| `KCxxxx.L02`、儀器 `.CSV` | 這次用到的**圖根點**，跟 .CTL 整理結果比對，差超過 2 公分就警告 |
| `*.B90` | **協助指界計算**：「由哪個測站、後視哪點、測到哪個補點」，補點名字會跟著改成清冊的編號 |

- 補點號碼**不會重複使用**：上傳刪掉後，那幾個號碼也不會再發出去。
- 補點跟**別的測量員**的補點在同一位置時，會提醒「可能是同一點」。

## 三之二、外業工具：永遠在 97 作業

**① 出發前：下載 97 外業包**（🧰 外業工具）：填地號，下載一份衛星接收儀格式的 CSV（`點名,N,E,0.000,`），全部是 TWD97：
附近的圖根點、補點（先列）和宗地界址點（後列）。67 段已經換好。

**② 回來：97 成果寫回重測系統**：選測量員、選這段重測系統的資料夾（例如 `KC0370`，裡面有 D14、D20）、選 97 外業成果（衛星接收儀 CSV、Nikon RAW），按「檢查」：

1. 數字點號對到這段界址點、點名對到圖根點的，是**重測到的舊點**：不寫入，拿來做檢查和局部修正。
   點名是流水號、**代碼欄寫點名**的（例如 `6,…,hl86`、`1,…,q2`）也認得；沒寫點名、但位置就在 D20 補點或圖根點 10 公分內的，也自動當成舊點。
   代碼不是數字編碼、又對不到舊點的新點，寫成參考點時編碼先用 11（會提醒）；同一批裡 6 公分內的兩點會提醒「可能同一點測兩次」。
2. Q 開頭 → D20 補點（照補點清冊編號）；數字點號＋編碼 → D14 參考點（同資料轉換系統的規則，6 公分內同點視為重測、預設不寫）。
3. 67 段：用這段同一組參數**反算回 67**（來回誤差 < 0.1 mm）。
4. **案件局部修正**：用這件案子 200 公尺內重測到的舊點，1～2 點平移、3 點以上四參數，讓新點跟旁邊的舊 67 資料接得上。
   修正後還超過容許差（預設 6 公分；5 公分起提醒）的點不拿來修正，並標紅。
   測試：模擬這一區轉換偏 5.4 公分，局部修正後 4 個舊點殘差 0.0～0.1 公分，新補點、新參考點回到正確的 67 位置。
5. 原本就有 67 坐標的舊點**不會被改寫**（只寫新點）。
6. 按「寫入」：先確認檔案沒被改過 → 原檔備份成 `KC0370.D14.日期時間.bak` → 寫入；同時下載寫入對照表，平台也留一筆紀錄（補點進清冊，記下用的參數版本和局部修正結果）。

**實際案例（0370，113.06.27 衛星接收儀成果）**：平台換回 67 的坐標，跟測量員當時寫進 D14／D20 的只差 0.8～1.4 公分；
重測到的 HL86、HL62、HL61、Q2 跟已知差 0.7～5.4 公分，局部修正後 1.0～4.1 公分。

### 圖解區（參考圖層）

⚙ 管理 →「圖解區」放 `KCxxxx.D2B／D2C／D2D`：地圖上用咖啡色虛線畫出來，D2B 有段號地號的版本可以點選、搜尋（例如 `336 99`）。
坐標系統預設**自動判斷**（跟旁邊的數值區比，看當 67 還是當 97 對得上），也可以手動指定。圖解區只當參考，不參與換算、檢核、寫回。

## 四、案件時間軸、有案件的土地

- 地圖上點任何一筆土地 → 跳出 **📅 案件時間軸**：每次案件的日期、種類、測量員、收件號；按「看範圍」會畫出那一次測的宗地範圍。

- 「🕘 誰上傳了什麼」會列出每次的案件種類、地號、新增幾個補點。

## 五、查詢

- **🔍 查詢**：一個框框什麼都能打
  - 地號：`123`、`123-4`、`123之4`、`1114 123-4`（段代碼 + 地號）
  - 點名：`QW1`、`BHC339`（打開頭幾個字就好）
  - 測量員名字或收件號：列出那些上傳
- 地圖點一下任何東西都會跳出說明；**📋 複製坐標** 可以貼到其他程式。

## 六、TWD67 的段：全部換成 TWD97

**哪些段是 67**：兩種方法一起用，結果在 **⚙ 管理 → 坐標系統** 看得到，也可以手動改。

1. 段名表（Excel）裡**紅字**的段（67 數值）。
2. **自動偵測**：相鄰的段，界址點會完全重合。67 的段用公式轉成 97 之後，會跟旁邊 97 段的界址點「整批差一樣的量」重合 → 就知道它是 67。
   互相重合的段一定同一系統，所以會整群一起判斷。

| 結果 | 段 |
|---|---|
| 段名表紅字、自動偵測都說 67 | 0346～0353、0357～0365、0370、0375～0377 |
| 只有段名表紅字（旁邊沒有 97 的段可以比） | 0367、0378、0379、0380 |

**廢段**：0326、0371、0372、0373、0374 是已經廢掉的 67 段，界址點跟現行的段重合，預設不顯示、也不拿來判斷（⚙ 管理可以改）。

**沒有參數檔的段怎麼換**：不用一般的近似公式（誤差 1～2 公尺），而是用 67 段跟旁邊 97 段**共同的界址點**算六參數轉換，每一群各算一組：
殘差 0.6～4.2 公分。0367、0378～0380 旁邊都是圖解區，沒有 97 數值段可以比，用全區共同點的參數（殘差約 6 公分）。

**圖根點要每一點各自判斷**：大份的 CTL（2,000 多行）是好幾段**共用的同一份檔**（例如 KC0323 和 KC0350 的 CTL 一模一樣，一個是 97 段、一個是 67 段），
裡面 67、97 混在一起，不能用「這檔在哪一段」判斷。判斷順序：

1. 只出現在非共用 CTL 的點 → 跟那段一樣。
2. 看位置：離 67 段的界址點很近、離 97 的很遠 → 67；反過來 → 97。
3. 看同一份 CTL 前後 15 行判斷出來的點（CTL 通常一批一批測的）→ 85% 以上同一系統就跟著（拿已知的點抽測，準確率 99.25%）。
4. 還是判斷不出來（163 點）→ 照原值當 97，在問題清單「看不出 67 或 97」列出來，地圖上點開也會提醒。

測量員上傳 67 段的資料，也會自動換成 97 顯示（原始坐標保留在說明裡），比對圖根點時用原始坐標比，不會被轉換誤差影響。

### 各段轉換參數檔（最準，優先用）

有做過 GPS 共同點的段（例如社柑段 0367），把那一段的轉換參數資料夾或 zip 放進 **⚙ 管理 → 各段轉換參數**，平台會自動找裡面的 `段號.inp`
（格式：`點名 權 N97 E97 N67 E67`，就是地籍坐標轉換程式的輸入檔），那一段就改用它：

1. **六參數仿射**（權 0 的點不用），結果跟轉換程式的 `.out` 一樣（社柑段：標準誤差 1.47 公分，18 點殘差都對得上）。
2. **最小二乘配置法殘差內插**（線性協方差，同 `interp.out` 的做法）：共同點上完全吻合，離共同點越遠越接近六參數結果。
3. 那幾個 GPS 實測過的圖根點，**直接用實測的 97 坐標**，不再用推算的。
4. **自動檢查**：
   - 可疑點：殘差比別人大很多（社柑段是 HB202，殘差 5.3 公分，跟 HB203 只隔 74 公尺卻差 5 公分）。
   - 外圍點：拿掉它旁邊就推不準（社柑段是 GA13，在南邊邊緣）。
   - 邊長檢核：兩點 97 距離 vs 67 距離，分 1/5000～1/20000 等級（同 chkdist.000～004）。
   - 外插範圍：段內離最近共同點超過 500 公尺的界址點比例（社柑段 12%，在南端）。

**一份參數檔給好幾段**：資料夾名寫「378、379、380」（或檔名 `KC0378_KC0379_KC0380.inp`），三段會共用同一組共同點。

**zip 裡有好幾份 .inp 時**：用「計算成果」裡**有 .out 一起、日期最新**的那份（正式算過的）；檔名有「經緯度」的不用；其他版本會列出差在哪幾點。
例如 378～380：用 `計算成果\1140819\380.inp`（15 點）；最上層的 `380.inp` 多了 HB160（跟其他點推算差 8.4 公分，正式計算時拿掉了），`1140723` 只有前 4 點。

**資料夾的段號**：「346-353」是範圍（8 段）；子資料夾自己有段號的（例如 `370_375_376\375\`）就只給那段；日期資料夾同一天有後綴的（`1140701_2`、`1140703_剔除HL129`）是修正版，優先用。
**原有圖根改算.txt**（點名 改算前N E 改算後N E）一起放進來就會套用：CTL 裡還是舊坐標的圖根點改成新的再換算。

**同一段有好幾份參數可以用時**（例如 375 有自己的、也在 370 那組裡）：拿這段附近 300 公尺內的共同點來考（自己有的點先拿掉再推），平均差最小的自動選用；
在這段範圍內有 3 點以上共同點的參數檔，就算檔名沒寫這段也會一起比。管理頁可以「改用這份」手動指定，也可以把某幾點取消勾選（不用），會重新計算。

轉換方法優先順序：**轉換參數檔** → 鄰段共同界址點 → 全區共同點。管理頁會列出每一段用哪一種、大約多準。

用 GPS 實測的 97 當標準答案比較：社柑段原本的全區參數平均差 6.9 公分（最大 15.1）；新復北／南／東段原本平均差 20.6 公分（最大 27.3）。改用參數檔後共同點上 0 公分，標準誤差 1.5 公分、2.1 公分。

### 第二層：外業檢核點（持續加密）

參數（第一層）只由管理者更新。日常外業用來發現、修正局部偏差：

1. 測量員上傳時，第 3 步可以加 **實測檢核點**（CSV／TXT，一行一點 `點名,Y,X`，TWD97 實測）：現場用 97 測到、本來就有 67 坐標的點。
   - 數字點名 → 對這次上傳 D14 的界址點；其他點名 → 對圖根點（CTL 整理結果）。對不到的會列出來。
2. 平台算「實測 − 換算」，看附近 150 公尺內其他檢核點來分類（地圖上畫成箭頭，放大 500 倍）：
   - 🟣 **區域偏差**：附近好幾點偏同一方向、差不多大 → 這一區轉換有偏差。
   - 🟠 **單點差**：只有這點跟旁邊不同 → 點本身的細部差（房屋、圍牆、舊測量），**不改參數**，只記錄。
   - 🟢 在容許差內（預設 3 公分，管理頁可調）；⚪ 附近檢核點不夠，還看不出來；🔴 差超過 1 公尺（多半點名對錯）。
3. 管理者在 **⚙ 管理 → 外業檢核點** 勾選區域偏差的點，按「加進內插」：
   - 只修正那幾點附近 500 公尺；GPS 共同點固定不動；遠的地方完全不受影響。
   - 權重比 GPS 圖根點低（不會硬拉到完全吻合）。
   - 加進去之後，「現在的差」會變小（測試：6 公分 → 0.4～0.8 公分）；隨時可以拿掉。
   - 確認過的點存在 `底圖\轉換參數\檢核點.json`。

**儀器檔會自動讀**（不用另外整理檢核點檔）：
- **衛星接收儀 CSV**（`點名,N,E,高程,編碼`）：高程 0、沒編碼的是上傳的已知點（拿去跟圖根點檔比「不符」）；有高程或編碼的是實測點，
  其中有點名的（例如實測的 GAC02）自動當檢核點；數字點號是細部點，不當檢核點。
- **Nikon RAW**：UP 已知點、ST 測站、F1 後視、SS 前視。平台會算出每個前視點坐標，有點名的實測點當檢核點；每次設站都做**後視檢核**（觀測水平距 vs 坐標反算），
  同時算「不改正」和「改算到 TM2 平面（尺度比＋高程）」兩種，管理頁累積統計，看這一帶的坐標是用哪一種距離算的。
- 先判斷檔案是 67 還是 97 坐標（已知點／實測點對圖根點；對不到就看離這次上傳的界址點近不近）。**只有 97 坐標的實測點拿來檢核 67→97 轉換**；
  67 坐標的只做「67 內部檢核」（實測 vs 已知，例如 QT60-2 vs QT60）。
- 同名但差好幾公尺以上的圖根點當作「不是同一點」，不會報不符。
- **67 段的上傳資料要不要換算**：看這次用到的圖根點（L02、儀器檔已知點）對到 67 坐標還是 97 坐標，多數決。
  對到 97 → 測量員已經用 97 作業，不再換算；對到 67 → 換成 97；都沒有 → 先當 67 換算並提醒。

**所有參數檔都不用的點**：管理頁可以列點名（目前預設 HL129），每份參數檔都不用那幾點。

## 七、圖根點（.CTL）為什麼要「整理」

轄區的 .CTL（不含廢段）合起來 74,197 行，但實際只有 13,522 個點，而且很亂：

| 問題 | 數量 | 平台怎麼處理 |
|---|---|---|
| 同一點在很多段重複出現 | 大部分 | 合併成一點，記錄出現在哪些段 |
| **同名不同點**（例如 `A1`、`A10` 在不同地區代表不同的點，相距好幾公里） | 1,826 個點名 | **用「點名＋坐標」分群**，相距 10 公分以上就當不同點，編成 `A1#1`、`A1#2`，點開會提醒 |
| 同一點各段坐標差一點點（例如差 1.7 公分） | 331 | 取出現最多次的坐標，並標示最大差值 |
| 假設坐標（例如 `Q5A 3182.303 5000.000`） | 9 | 不放到地圖上，列在問題清單 |
| X 坐標是 0 | 1 | 同上 |
| 點名裡夾 tab、點名剛好 8 字和 Y 黏在一起（`QHB186-1`、`L129+580`） | 146 | 依固定欄寬讀取（點名 8、Y 11、X 10） |
| X 後面多一碼（`215848.4905`、`…1634A`） | 1,860 | 照轉換系統的固定欄寬捨去 |
| Y、X 寫反 | 0（有防） | 整數 7 位是 Y、6 位是 X（同轉換系統），自動對調 |

**⬇ 標準格式 CTL（TWD97）**：每段一份，全部是這種格式（點名 8、Y 11、X 10、小數 3 位）：

```
BE20    2697345.532219817.771
```

另附 `全區圖根點_TWD97.CTL`（去掉重複）和 `整理說明.txt`（每一行改了什麼、哪些行拿掉、哪些是 67 換過來的）。

**⚙ 管理** 裡可以看問題清單（點一下就飛到那點），也可以下載整理後的圖根點 CSV。

## 八、改版

有新版的 `地籍共作平台.html` 時，**直接覆蓋共用資料夾裡的舊檔就好**，不用額外設定：

- 資料都在 `地籍共作平台資料` 資料夾裡，跟 HTML 檔是分開的，覆蓋 HTML 不會動到資料。
- 新版會讀得懂舊版存的資料（舊的上傳沒有案件種類、地號，照樣顯示）。
- 大家下次打開（或按 F5 重新整理）就是新版。目前版本寫在 **⚙ 管理 → 共用資料夾** 那一格。
- 只有底圖的整理方式改了的時候，才需要管理者在 ⚙ 管理 按一次「重新整理」（會在改版說明裡寫）。

## 九、開發

```
node tests/test_core.js                 # 共用資料夾版核心測試
python -m unittest discover tests       # Python 版測試
python tools/build_nas.py               # 打包成 dist/地籍共作平台.html
```

- `nas/core.js`：所有檔案格式讀取、67→97、圖根點整理、底圖建立（瀏覽器與 Node 都能跑；跟 Python 版用真實資料比對過，結果一致）
- `nas/store.js`：讀寫共用資料夾（File System Access API）
- `nas/app.js`、`nas/index.html`、`nas/style.css`：畫面
- `dist/地籍共作平台.html`：打包好的單一檔案（Leaflet、段名都包在裡面）
- `tools/共用資料夾測試.html`：測試瀏覽器能不能讀寫共用資料夾

### 另一種用法：伺服器版（`server/`）

如果之後資訊單位同意架一台主機（或要放雲端讓手機也能看），可以用伺服器版：
`python server/app.py`（只用 Python 內建模組），資料放 `data/`，設定 `ACCESS_PASSWORD` 環境變數可以加共用密碼，
`render.yaml` 是 Render 雲端的部署設定（免費方案沒有硬碟，要付費方案）。功能跟共用資料夾版一樣。
