# 地籍共作平台

讓測量員外業回來，把**重測系統的資料夾**丟上來，大家就能在同一張地圖上看到彼此的**補點、參考點**，並對照**數值地籍圖**與整理過的**圖根點**。

- 不用安裝任何套件：只要一台裝了 **Python 3.8 以上** 的電腦當「主機」（或放到 Render 雲端），其他人用瀏覽器打開網址就能用。
- 坐標一律換成 **TWD97**（67 的段自動找出來、用共同點換算）。
- 資料都存在主機的 `data/` 資料夾，不會傳到外面（只有底圖圖磚會向國土測繪中心要；沒網路也能用，只是沒有底圖）。

## 一、架設

有兩種方式：**A. 放在所內一台電腦**（免費、資料不出所）或 **B. 放到 Render 雲端**（外業用手機也能連，每月約 7.25 美元）。

### A. 所內電腦

1. 主機安裝 Python 3（<https://www.python.org>，安裝時勾 **Add python.exe to PATH**）。
2. 把整個專案資料夾放到主機上，例如 `D:\地籍共作平台`。
3. 把轄區的數值地籍圖（例如 `115-11-01數值.zip`，或解開後的 `KC0308`、`KC0309`… 資料夾）放進 `data\base\`。
   - 沒有 `data\base` 就自己建一個；也可以開平台後在 **⚙ 管理 → 更新數值地籍圖** 上傳。
4. 雙擊 **`啟動平台.bat`**。第一次會整理底圖（82 段大約 10 秒），視窗會顯示網址，例如：
   ```
   http://192.168.1.23:8080
   ```
5. 把這個網址給大家（可以做成桌面捷徑或書籤）。視窗不要關，關了平台就停了。

> 換埠號：`啟動平台.bat --port 9000`；資料放別處：`啟動平台.bat --data E:\平台資料`
>
> Windows 防火牆第一次會問要不要允許 Python 連線，請選「允許（私人網路）」。

### B. 放到 Render（https://render.com）

> 免費方案**不能掛硬碟**，重新啟動資料就不見了，一定要選 **Starter（約 7 美元／月）+ 1 GB 硬碟（0.25 美元／月）**。
> 放在網路上任何人都連得到，所以一定要設**共用密碼**（`ACCESS_PASSWORD`）。

1. 到 <https://render.com> 用 GitHub 帳號註冊／登入。
2. 右上角 **New → Blueprint**，選這個 repo（`Map-Collaboration`），分支選有這份程式的分支。
3. Render 會讀 `render.yaml`，自動建立網站和硬碟。畫面會要你填 **ACCESS_PASSWORD**：填一個大家共用的密碼。
4. 按 **Apply**，等 2～3 分鐘，會出現網址，例如 `https://map-collaboration.onrender.com`。
5. 打開網址、輸入密碼 → **⚙ 管理 → 更新數值地籍圖 → 選 zip**，把數值 zip 傳上去（地籍資料不放在 GitHub）。
6. 把網址和密碼給大家就好。之後改程式推到 GitHub，Render 會自動更新，資料在硬碟上不會不見。

要換密碼：Render 網站 → 這個服務 → **Environment** → 改 `ACCESS_PASSWORD` → Save（會自動重啟）。

## 二、測量員：上傳外業資料（3 步）

1. 按綠色 **📤 上傳外業資料**，填名字（第一次填就會記住）。
2. 把重測系統的資料夾（例如 `383` 或 `KC1114`）**整個拖進框框**，或按「選資料夾」／「選檔案 / zip」。
3. 看系統讀到的內容（補點幾點、參考點幾點、圖根點有沒有不符），沒問題按 **✅ 上傳**。

系統會自己挑需要的檔案，其他的（NTX、MTX、xls…）自動略過：

| 檔案 | 讀出什麼 |
|---|---|
| `KCxxxx.D20` | **補點**（D20 裡全部都是 Q 開頭的補點） |
| `KCxxxx.D14` | **參考點**（COT_REF 編碼不是 00 的點，顯示成 `5.30` 這種點號） |
| `KCxxxx.L02`、儀器 `.CSV` | 這次用到的**圖根點**，會跟 .CTL 整理結果比對，差超過 2 公分（可調）就警告 |
| `*.B90` | **協助指界計算**：記錄「由哪個測站、後視哪點、測到哪個補點」，地圖上畫綠色虛線 |
| 沒有 D20／D14 時 | 退而用 `L20`（補點）、`L14`（編碼非 0 的參考點） |

- `KC0000.L02` 是重測系統預設檔，會略過。
- 資料夾外面、看不出段別的檔（例如 `11304161.CSV`），上傳內容只有一個段時會自動歸到那段。
- 同一個人、同一段再傳一次，**新的蓋掉舊的**；舊的上傳紀錄還在「🕘 誰上傳了什麼」，可以下載原始檔或刪除。
- 兩個人上傳同名補點但坐標差超過容許值 → 地圖上那點會**閃爍**，點開看得到兩人的坐標。

## 三、查詢

- **🔍 查詢**：一個框框什麼都能打
  - 地號：`123`、`123-4`、`123之4`、`1114 123-4`（段代碼 + 地號）
  - 點名：`QW1`、`BHC339`（打開頭幾個字就好）
  - 測量員名字：列出他的上傳
- 地圖點一下任何東西都會跳出說明；**📋 複製坐標** 可以貼到其他程式。
- 右下角可以勾選要顯示哪些圖層、換底圖、只看某個人的資料。
- 放大到一定程度才會出現圖根點（15 級）和地籍線（16 級），地號文字在 18 級。

## 四、TWD67 的段：全部換成 TWD97

**哪些段是 67**：兩種方法一起用，結果在 **⚙ 管理 → 坐標系統** 看得到，也可以手動改。

1. 段名表（Excel）裡**紅字**的段（67 數值）。
2. **自動偵測**：相鄰的段，界址點會完全重合。67 的段用公式轉成 97 之後，會跟旁邊 97 段的界址點「整批差一樣的量」重合 → 就知道它是 67。
   互相重合的段一定同一系統，所以會整群一起判斷。

| 結果 | 段 |
|---|---|
| 段名表紅字、自動偵測都說 67 | 0346～0353、0357～0365、0370、0375～0377 |
| 只有段名表紅字（旁邊沒有 97 的段可以比） | 0367、0378、0379、0380 |
| 段名表沒有、自動偵測說 67 | **0326、0372、0373、0374**（0371 跟 0378～0380 界址點重合，一起算 67） |

**怎麼換**：不用一般的近似公式（誤差 1～2 公尺），而是用 67 段跟旁邊 97 段**共同的界址點**算六參數轉換，每一群各算一組：
殘差 0.6～3.4 公分。旁邊沒有 97 段可以比的（0367、0371、0378～0380）用全區共同點的參數（殘差約 7 公分）。

**圖根點要每一點各自判斷**：大份的 CTL（2,000 多行）是好幾段**共用的同一份檔**（例如 KC0323 和 KC0350 的 CTL 一模一樣，一個是 97 段、一個是 67 段），
裡面 67、97 混在一起，不能用「這檔在哪一段」判斷。判斷順序：

1. 只出現在非共用 CTL 的點 → 跟那段一樣。
2. 看位置：離 67 段的界址點很近、離 97 的很遠 → 67；反過來 → 97。
3. 看同一份 CTL 前後 15 行判斷出來的點（CTL 通常一批一批測的）→ 85% 以上同一系統就跟著。
4. 還是判斷不出來（139 點）→ 照原值當 97，在問題清單「看不出 67 或 97」列出來，地圖上點開也會提醒。

測量員上傳 67 段的資料，也會自動換成 97 顯示（原始坐標保留在說明裡），比對圖根點時用原始坐標比，不會被轉換誤差影響。

## 五、圖根點（.CTL）為什麼要「整理」

轄區 82 段的 .CTL 合起來 85,332 行，但實際只有約 13,500 個點，而且很亂：

| 問題 | 數量 | 平台怎麼處理 |
|---|---|---|
| 同一點在很多段重複出現 | 大部分 | 合併成一點，記錄出現在哪些段 |
| **同名不同點**（例如 `A1`、`A10` 在不同地區代表不同的點，相距好幾公里） | 1,834 個點名 | **用「點名＋坐標」分群**，相距 10 公分以上就當不同點，編成 `A1#1`、`A1#2`，點開會提醒 |
| 同一點各段坐標差一點點（例如差 1.7 公分） | 334 | 取出現最多次的坐標，並標示最大差值 |
| 假設坐標（例如 `Q5A 3182.303 5000.000`） | 9 | 不放到地圖上，列在問題清單 |
| X 坐標是 0 | 1 | 同上 |
| 點名裡夾 tab、點名剛好 8 字和 Y 黏在一起（`QHB186-1`、`L129+580`） | 146 | 依固定欄寬讀取（點名 8、Y 11、X 10） |
| X 後面多一碼（`215848.4905`、`…1634A`） | 1,860 | 照轉換系統的固定欄寬捨去 |
| Y、X 寫反 | 0（有防） | 整數 7 位是 Y、6 位是 X（同轉換系統），自動對調 |

**⬇ 標準格式 CTL（TWD97）**：每段一份，全部是這種格式（點名 8、Y 11、X 10、小數 3 位）：

```
BE20    2697345.532219817.771
```

另附 `全區圖根點_TWD97.CTL`（去掉重複）和 `整理說明.txt`（每一行改了什麼、哪些行拿掉、哪些是 67 換過來的）。

**⚙ 管理** 裡可以看問題清單（點一下就飛到那點），也可以下載整理後的圖根點 CSV。

## 六、資料放在哪

```
data/
  base/            數值地籍圖（放 zip 或 KCxxxx 資料夾）
  cache/           自動產生的底圖快取（刪掉會重建）
  uploads/         每次上傳的原始檔（1.zip、2.zip…）
  platform.sqlite  上傳紀錄與點位
  config.json      設定（67 段清單、容許差、段名）
```

**備份只要複製整個 `data` 資料夾。** `data/` 不會進 git（地籍資料不該放上 GitHub）。

## 七、開發

```
python -m unittest discover tests     # 測試
python server/app.py --port 8080      # 啟動
```

- `server/parsers.py`：所有檔案格式的讀取（參考「土地重測資料轉換系統」的規則）
- `server/datum.py`：判斷 67 段、用共同點算 67→97 轉換參數
- `server/basemap.py`：數值地籍圖 → 每段一個 JSON（全部 97）、圖根點逐點判斷坐標系統與整理
- `server/section_names.json`：預設段名（從段名表 Excel 匯入）
- `server/app.py`：HTTP 伺服器、SQLite
- `web/`：網頁（Leaflet 1.9.4 已內附，不用連外網）
